# tv-mobile (`tv-mobile`)

The single Expo app (phone, tablet, TV; Android, Fire OS, Apple): a composition root that wires modules, storage drivers, routes and stores.
## Commands
- `pnpm run:app <target> run|build` launches or prebuilds a target. `pnpm --filter tv-mobile test` runs Vitest, `test:jest` Jest.
  `exec expo-doctor` and `exec expo install --check` (`pnpm --filter tv-mobile`) are release gates.

## Rules
- `android/` and `ios/` are generated by `expo prebuild`; never edit or commit them. Placeholder images in `assets/` are generated once; replace them with art, not code.
- `app.config.ts` only calls `config/build-app-config.ts`; put logic and tests there.
- Build variants come from env: `APP_VARIANT` (development|production), `EXPO_TV=1`, `STORE` (play|amazon|appstore|direct). No Gradle product flavors.
- `DEV_*` values reach `extra.dev` in development only; production builds never contain them. `config/with-dev-cleartext.ts` (development only) limits cleartext HTTP to
  `10.0.2.2`, `127.0.0.1`, `localhost` through a network security config; iOS uses ATS `NSAllowsLocalNetworking`.
- One `react-native` copy (the root override aliases it to `react-native-tvos`). No Google Play Services or Firebase.
- Phone and TV targets share `android/` and `ios/`. `pnpm run:app` stamps the folder (`.elv-prebuild.json`) and regenerates it
  when the target, variant or store changes. After changing `app.config.ts`, plugins or native dependencies, run `pnpm run:app <target> build`.

## Development gate (`src/gate/`)
- Deep link `elviptv://gate/list?items=100000&auto=1&rate=20&moves=600` opens `GateListScreen`. The scheme `elviptv`
  is registered in every variant; the screen is reachable only when `extra.gate` is `true`, which
  `build-app-config.ts` sets for `APP_VARIANT=development` only. The app reads it with `expo-constants`; never key it
  on `__DEV__` (the gate is measured on a JS-bundled release build of the development variant).
- `parseGateUrl` (`routes.ts`) clamps: items 1 to 1,000,000, rate 1 to 60/s, moves 1 to 10,000, `stall` 0 to 200 ms (one busy-wait
  mid-run to calibrate the JS gap); defaults 100,000 / manual / 20 / 600 / 0. `useGateParams` reads the iOS/tvOS launch argument `-gateUrl <url>`
  (`Settings`; skips the tvOS "Open in …?" prompt of `simctl openurl`), else the initial URL and `url` events (`Linking`); without the flag, nothing.
- Auto run: `createAutoDriver` (`driver.ts`) emits a scripted sequence through the focus store: a down-hold (`long`
  page then `repeat` steps), page jumps (`channelDown`), single presses, then the mirror going up. It ends at index 0
  when the list is longer than the deepest excursion (about 600 rows at 600 moves); an odd `moves` is rounded down.
  A `repeat` arriving before the previous move committed is dropped (`coalesced`); `scripted` counts every driver event.
- Real keys: `App` wraps both branches in `RemoteKeysProvider android={remoteKeys}` (`@elv/remote-keys`), so on Android raw key
  events feed `useTvKeySource`; elsewhere `TVEventHandler` does, which needs the `focusable` root with `hasTVPreferredFocus`.
  `useTvKeySource` -> `createKeyInterpreter` -> store; the ticker runs while a key is down and stops on `up` or `cancel`; repeats
  are acknowledged from `onFrameCommitted`. With `auto=0` it prints one line after 2 s without a move (`--real-keys`).
- Metrics (`metrics.ts`): `t0` is the dispatch time (auto) or the key's first input (real: the `down`, back-dated by its age at JS receipt, at most 100 ms); `t1` is `performance.now()` in
  `onFrameCommitted` (first frame after row and ring committed); key-to-highlight is `t1 - t0` per move that commit covers.
  `maxJsGapMs` is the longest synchronous work of a move (dispatch to the end of the list commit, ended by `CommitProbe`);
  `maxFrameStallMs` estimates stalls outside dispatch: slowest `requestAnimationFrame` delta minus 0.7 of the median (a 4 ms
  `setInterval` fires once per frame, so it cannot see tasks). Resolution about one frame: `stall=30` reads >= 16 ms, `stall=20`
  does not reliably; idle jitter stays below 16. The tools gate only warns about it on emulators; hardware will enforce it.
- `losses`: a committed frame whose focused index is outside `[0, items)`, outside the visible window that `TvList` reported for
  that frame, or outside the rows it rendered; plus 1 if the last committed index differs from the store's index once
  the run settles; plus every move that never got a committed frame (after a 2 s settle timeout). Moves whose net effect
  left the index unchanged within a frame (A to B to A) get no `TvList` callback; the screen resolves them in its own
  animation frame and they are not losses. Unmounting or changing the params mid-run prints nothing for that run.
- Import gate: `elviptv://gate/import?host=10.0.2.2:7878&account=large|huge&batch=500..20000` (`src/gate/import/`, dev hosts only; `&maxBody=` KiB, 256..131072, default 4096) imports a simulator
  account into a new `gate-import-<time>.db`, prints one `ELV_GATE_IMPORT {account,batch,maxBody,rows,durationMs,maxStallMs}` line (`error` on failure);
  `maxStallMs` = longest gap of a 16 ms `setInterval` minus 16 during the import.
- Output: one `'ELV_GATE ' + JSON.stringify(metrics)` line per run (`intents`: counts of the six intent kinds, zeros kept), `console.log`
  on Android (logcat `ReactNativeJS`), `console.error` on iOS (release builds drop info logs). Pure gate tests run in Vitest
  (`src/gate/**/*.test.ts`), component ones in Jest on fake timers (`advance` in `__tests__/gate-test-utils.ts`).
