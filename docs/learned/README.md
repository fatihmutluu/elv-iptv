# Lessons learned

Short dated entries: problem, then the rule that follows.

- 2026-11-13 Windows MAX_PATH breaks Expo Android ninja builds ("still dirty" path errors). Enable `LongPathsEnabled` or install with `pnpm install --virtual-store-dir C:\v`; `subst` does not help.
- 2026-11-13 The gitleaks GitHub Action fails on a repository's root commit. CI runs the gitleaks CLI instead.
- 2026-11-13 A file name containing `&` becomes command injection when passed through a shell. Stop and agent hooks never pass file names through a shell.
- 2026-11-13 release-please PRs opened with `GITHUB_TOKEN` do not trigger CI. Use a token that does, or trigger checks explicitly.
- 2026-11-13 Development builds embed `DEV_*` values in the app config `extra`. Development builds are never given to testers. Release builds must never contain `DEV_` values; a CI gate on release artifacts is planned.
- 2026-11-13 pnpm's minimum release age blocks just-published versions. Use `minimumReleaseAgeExclude` only for a time-boxed, commented exception.
- 2026-11-13 Sandboxed Electron preload scripts must be CommonJS; an ES module preload fails to load.
- 2026-11-13 Electron 45 downloads its binary lazily on first run, so there is no postinstall script to allow in pnpm.
- 2026-11-13 Expo's config loader needs the explicit `.ts` extension for TypeScript imports from `app.config.ts`.
- 2026-11-13 TV list gate baseline (`docs/learned/gates/list-android-tv.json`; Android TV emulator `elv_tv`, `sdk_google_atv64_x86_64`, Android 16 / API 36; development variant release APK with bundled JS, debug-signed; `pnpm gate list --runs 3 --real-keys 60`; 100,000 items, 600 moves at 20 per second): key-to-highlight p50 17.8 / p95 19.3 / max 21.0 ms, JS gap (longest synchronous work of a move, enforced) 5.1 ms (runs 4.95 / 5.21 / 5.11; budget 16), frame stall (report-only) 10.5 ms (runs 10.46 / 10.91 / 10.36), 0 losses, 0 coalesced, real D-pad keys p95 22.4 ms, 605 frames (p50 17 / p95 18 / p99 19 ms), legacy janky 0.5 %; measured at commit 333f2ec. Three surprises. (1) A 4 ms `setInterval` fires once per frame on Android (16.7 ms at idle, 22 ms worst), so the first JS-gap sampler measured frame quantisation and could never meet 16 ms; the gap is now only the per-move synchronous work, and tasks outside dispatch are estimated by a separate report-only field, `maxFrameStallMs` (slowest `requestAnimationFrame` delta minus 0.7 of the median). Calibrated with the `stall=<ms>` gate parameter on the emulator: no stall 10.2 / 10.6, 20 ms stall 9.9 / 10.3 / 12.3 (not detected: the delay is the stall plus the phase in the frame, 20 to 36 ms, which idle vsync slips of up to 27 ms imitate), 30 ms stall 18.5 / 18.5 / 18.5; a median-relative overshoot read the 30 ms stall as only 13.4. Resolution is about one frame. A tight `setImmediate` loop to see tasks directly starves the app (the run never finishes). (2) `adb shell input keyevent` reaches `TVEventHandler` only when a view has focus; a screen without a focusable view receives no remote keys. (3) The deadline-based `Janky frames` figure of `dumpsys gfxinfo` swung between 50 and 73 % across identical runs (host-GPU draw commands are slow) while the legacy figure stayed at 0.5 to 0.8 %; the gate enforces the legacy one and only warns about the other. The emulator's Google TV launcher can also open a dialog over the app after launch; the runner presses Back and restarts once, then fails naming the blocking activity.
