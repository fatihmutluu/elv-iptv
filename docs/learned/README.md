# Lessons learned

Short dated entries: problem, then the rule that follows.

- 2026-11-13 Windows MAX_PATH breaks Expo Android ninja builds ("still dirty" path errors). Enable `LongPathsEnabled` or install with `pnpm install --virtual-store-dir C:\v`; `subst` does not help.
- 2026-11-13 The gitleaks GitHub Action fails on a repository's root commit. CI runs the gitleaks CLI instead.
- 2026-11-13 A file name containing `&` becomes command injection when passed through a shell. Stop and agent hooks never pass file names through a shell.
- 2026-11-13 release-please PRs opened with `GITHUB_TOKEN` do not trigger CI. Use a token that does, or trigger checks explicitly.
- 2026-11-13 (Superseded by the 2026-11-15 `release-hygiene` entry below.) Development builds embed `DEV_*` values in the app config `extra`. Development builds are never given to testers. Release builds must never contain `DEV_` values; a CI gate on release artifacts is planned.
- 2026-11-13 pnpm's minimum release age blocks just-published versions. Use `minimumReleaseAgeExclude` only for a time-boxed, commented exception.
- 2026-11-13 Sandboxed Electron preload scripts must be CommonJS; an ES module preload fails to load.
- 2026-11-13 Electron 45 downloads its binary lazily on first run, so there is no postinstall script to allow in pnpm.
- 2026-11-13 Expo's config loader needs the explicit `.ts` extension for TypeScript imports from `app.config.ts`.
- 2026-11-13 A 4 ms `setInterval` fires only once per frame in React Native on Android, so an event-loop sampler measures frame quantisation, not JS tasks. Measure JS work directly (dispatch to end of commit); estimate other stalls from `requestAnimationFrame` deltas, which resolve about one frame (a 30 ms stall shows, a 20 ms one does not).
- 2026-11-13 A tight `setImmediate` loop that watches for JS tasks starves the app. Never busy-loop to observe the event loop.
- 2026-11-13 Android TV delivers no remote keys to `TVEventHandler`, not even `adb shell input keyevent`, while no view has focus. Every TV screen needs a focusable root with `hasTVPreferredFocus`.
- 2026-11-13 The deadline-based "Janky frames" of `dumpsys gfxinfo` swung between 50 and 73 % across identical emulator runs while the legacy figure stayed below 1 %. On emulators enforce the legacy figure and only warn about the deadline one.
- 2026-11-13 The emulator's TV launcher can open a dialog over a freshly launched app. Gate runners check the resumed activity, press Back and retry once, then fail naming the blocker.
- 2026-11-14 react-native-tvos 0.88 on Android TV delivers a D-pad tap to `TVEventHandler` only as its release, and a hold as one `long<Key>` start and release with no repeats. Step on the earliest event the runtime delivers (an `up` without a `down` is a press), drop the long release, and verify key handling on a device, not only in unit tests.
- 2026-11-14 (Superseded by the next entry: real keys are now measured from the press.) TV list gate baseline: `docs/learned/gates/list-android-tv.json` holds the device, build and numbers (commit 88de00a: key-to-highlight p95 19.3 ms, JS gap 4.3 ms, real keys p95 21.0 ms from the release, 0 losses on the API 36 emulator).
- 2026-11-14 The TV list gate measures real keys from the press (raw Android key events via `@elv/remote-keys`) and checks a 2 s Down hold (`--real-hold`, API 33+). Observed on API 28 and 36: on the API 36 emulator (`elv_tv`) the hold gave 13 moves as expected, a 1 s Back hold `backLong` 1 and `back` 0, real keys p95 22.5 ms with the age taken at JS receipt (so the native-to-JS wait counts), 0 losses (`docs/learned/gates/list-android-tv.json` re-recorded at commit cef1106); on the API 28 Fire OS 7 stand-in a 2 s hold gave 16 moves (expected 14 ± 3) and a 1 s Back hold `backLong` 1. On the API 30 Fire OS stand-in `adb emu event send` does not reach the app, and `input keyevent --longpress` is injected instantly (a tap); a real hold needs API 28 or 33+.
- 2026-11-14 Parsing one whole large JSON response blocks the JS thread for over a second (a 25,000-row Xtream list: about 1.2 s on the Android TV emulator), whatever the write batch size. Bound the response body (`DEVICE_MAX_BODY_BYTES`, 4 MiB) and load per category: the longest stall fell to 45 ms for about twice the import time. `pnpm gate import` guards it. On the Apple TV simulator (ad-hoc signed) the large import took 9,768 ms with a 17.9 ms max stall.
- 2026-11-14 FFmpeg cannot turn text into bitmap subtitles (`dvbsub` and `dvdsub` refuse text input) and has no teletext, PGS or caption encoder, so the simulator corpus has none; see [sim-format-gaps.md](sim-format-gaps.md). Copies of a multi-track file need `-map 0`: FFmpeg's default stream selection keeps one audio track.
- 2026-11-14 Media3 reconnects a dropped live MPEG-TS request on its own (its load retry, a fresh request from byte 0 about 0.8 s later): on the Android TV emulator a `drop@5s` froze the picture about 2 s and playback resumed while the service stayed `playing` (ladder L0), so a gate that waits for a recovery rung read it as a miss. Judge a drop by playback resuming (a stall of the current attempt that ends while the service plays counts) and check the drop and the reconnect in the simulator log.
- 2026-11-14 (Superseded by the OkHttp entry below: superseded requests are now cancelled at once.) A stalled stream connection does not close on `stop`: its socket read stays blocked, so a zap away from it waits for the engine's connection gate to force-close it after 1,000 ms (zaps of 1.5 to 2.0 s instead of about 0.5 s on the emulator). Keep that bound short and test zaps from a stuck channel (`fault=stall` on the player gate route).
- 2026-11-14 (Superseded by the re-recorded baseline below.) Player gate baseline: `docs/learned/gates/player-android-tv.json` (commit 0ed7e16, API 36 emulator, 3 runs of 30 zaps over H.264, HEVC and MPEG-2 channels): cold 741 ms, warm p50 465 ms, zap p50/p95/max 465/677/1,671 ms, 0 limit responses and 0 ms overlap on the one-connection account, one surface per run; drop5 recovered, 404 failed in time, 509 limited with its backoff. Host load moves these times a lot (an earlier run on a busy host had zap p95 1,430 ms), and one baseline run's cold start passed the 2 s first zap unmeasured.
- 2026-11-14 On Apple platforms `NSAllowsLocalNetworking` silently cancels `NSAllowsArbitraryLoads` (ATS ignores the arbitrary-loads key when both are set), so a development variant with only the local-networking key blocked plain-HTTP streams. Set `NSAllowsArbitraryLoads` alone.
- 2026-11-14 Media3's default HTTP data source cannot abort a request that is still connecting or waiting for its status line: it holds no connection object then, so `close()` does nothing, and a loader interrupt does not stop blocking socket I/O. A "force-closed" request stayed open beside the next media, which a one-connection provider sees as two connections (in a slow-start test the held request was answered 509 because the next channel was already open). Use Media3's OkHttp data source, cancel the call from the gate (OkHttp closes the socket in every phase), count a connection until its owner really closed it, and test with a withheld answer (`fault=slowstart` on the player gate route). Measured on the API 36 emulator: a slow-start zap left 0 ms overlap and no limit answer (before: 1.24 to 1.27 s overlap and one 509); zaps away from a stalled stream fell from 1.5 to 1.6 s to 0.5 to 0.7 s (6 of 7 runs; one run right after a build was slow on every zap, up to 3.2 s, with no gate wait logged).
- 2026-11-14 Player gate baseline re-recorded after the OkHttp change: `docs/learned/gates/player-android-tv.json` (commit 8f6c226, API 36 emulator, 3 runs of 30 zaps): cold 629 ms, warm p50 466 ms, zap p50/p95/max 466/657/700 ms, worst-run overlap 0 ms and 0 limit responses on the one-connection account, one surface per run; drop5 recovered, 404 failed in time, 509 limited with its backoff, slowstart left with no limit answer. Every run measured its cold start. Host load still moves these times (hand runs right after a build gave single zaps up to 1.9 s with the next request on time, later runs 0.4 s).
- 2026-11-15 `tools/bin/release-hygiene.ts` enforces release artifact hygiene in `native.yml` across Android phone, Android TV, Fire OS (`STORE=amazon`), iOS, tvOS and desktop `app.asar`: `releaseRuntimeClasspath` and merged manifests carry zero `com.google.android.gms` or `com.google.firebase` artifacts (`#11`), merged Android manifests carry zero legacy `READ_EXTERNAL_STORAGE`/`WRITE_EXTERNAL_STORAGE` permissions (`#19`) while preserving `usesCleartextTraffic="true"` (`#12`), Apple `Info.plist` files keep `NSAllowsArbitraryLoads` without `NSAllowsLocalNetworking` (`#12`), and exported release bundles, public `app.config` JSON and packaged `app.asar` archives contain zero `DEV_*` keys, `gate: true` flags or `.dev` identifiers.
- 2026-11-15 Production Electron fuses (`enableNodeCliInspectArguments: false`) disable `--inspect=0`, causing Playwright's `_electron.launch({ executablePath })` to time out waiting for the Node inspector WebSocket. Smoke-test packaged binaries (`#18`, `apps/desktop/e2e/packaged.spec.ts`) by spawning the executable with `--remote-debugging-port=0` and attaching Playwright over Chromium CDP (`chromium.connectOverCDP`).
- 2026-11-15 WHATWG `new URL('APP://ELV/a.js')` in Node lower-cases `url.protocol` (`'app:'`) without lower-casing `url.hostname` (`'ELV'`) because custom schemes are non-special, whereas Chromium's standard-scheme registration lower-cases both; compare `url.hostname.toLowerCase()`, reject non-empty `username`/`password`/`port`, and reject `:` in decoded relative paths so Windows NTFS alternate data streams (`index.html:$DATA`) never resolve.
- 2026-11-15 Running `@elv/sources` under standalone Hermes (`#37`, `tools/bin/hermes-sources.ts` in `ci.yml`) measured `1.84 MiB/s` (`13,432 entries/s`, 7.45 s) on the 100,000-entry `large` M3U (13.68 MiB) and `1.83 MiB/s` (`8,789 programmes/s`, 97.25 s) on the unfiltered 854,751-programme `large` XMLTV (178.05 MiB). Hermes provides `atob`/`btoa` natively (and `decodeUtf8` avoids `TextDecoder`), but leaves `Symbol.asyncIterator` `undefined` — and neither `react-native` nor `expo` polyfills it — so direct `body[Symbol.asyncIterator]()` calls throw `TypeError: undefined is not a function`. Use `isAsyncIterable` and `openAsyncIterator` (`@elv/domain`), which fall back to Babel's `'@@asyncIterator'` method with the receiver preserved (`polyfills=[]` on bare Hermes), and import `./src/polyfills` first in `apps/tv-mobile/index.ts` so `Symbol.asyncIterator` is installed before any module's `_AsyncGenerator` helper runs.
- 2026-11-15 Capping `down` backdating (`MAX_BACKDATE_MS`) independently from `up` while `up` uses live `now()` turns an 80 ms `Back` tap during a 520 ms JS stall into a false `backLong` (or crushes a 600 ms hold into `0 ms`). In `createAndroidKeyAdapter`, record `{ rawDownAt: now - downAgeMs, reportedDownAt }` alongside active `Set<number>` keyCode aliases per `Key`, stamp the final release at `reportedDownAt + Math.max(0, (now - upAgeMs) - rawDownAt)`, and pair with a 1-turn `> 100 ms` stall guard in `useKeyInterpreter` so queued `up` events drain before `tick()` fires `long`.
- 2026-11-15 Because `ForwardingWindowCallback` never consumes window keys on Android TV, focusing a `TextInput` without JS-side suspension lets D-pad arrows move underlying `TvList` rows and short `Back` pop the screen. Wrap screens in `TextEntryBoundary` and use `TvTextInput` (or `useTextEntrySuspension`, `#48`): entering text entry cancels held non-`back` keys, suppresses non-`back` keys while focused, consumes short `back` (`press`) to `blur()` the field, and still forwards `back` `long` (`backLong`).
- 2026-11-15 Storing `ForwardingWindowCallback` as a `WeakHashMap` value strongly references `Activity -> Window` and defeats garbage collection, while lockscreen-free Android TV standby may omit `onWindowFocusChanged(false)`. Track wrapped `Window` instances in a UI-thread `WeakHashMap<Window, Boolean>` in `KeyForwarding` and emit `blur` on `OnActivityEntersBackground` as well as `onWindowFocusChanged(false)`.
- 2026-11-15 Passing a list-wide `version` counter to memoized `TvList` rows re-renders every visible row on off-screen batch arrivals, and reading `index` without active-list state leaves ghost `<FocusRing />`s in inactive panes or empty lists. Pass `item={source.get(i)}` directly to memoized `<Row>` (quantizing `source.prefetch` bounds by half-pool steps) and pack `store.isActive(listId)` into `TvList`'s `useSyncExternalStore` snapshot (`isActive ? index : -(index + 1)`).
- 2026-11-15 Writing M3U `urlvars` to `SecretStore` only after SQLite marks an import `'ok'` leaves `{{...}}` templates permanently unplayable if Keystore/Keychain rejects the write (`ENOSPC` or locked store). Write `{ ...oldVars, ...newVars }` to `SecretStore` before committing SQLite cleanup (keeping in-flight zaps against old rows valid), restore prior chunks in `SecretStore.set` if an overwrite fails midway, prune superseded keys in `afterCommit`, and cap `urlvars` at 64 KiB (`source-format/urlvars-too-large`) so per-stream token playlists fail closed before mutating the active catalog.
- 2026-11-15 Connection-scoped SQLite pragmas (`busy_timeout`, `temp_store`, `foreign_keys`) do not carry across `op-sqlite` connections on the same WAL file, and interrupting the reader on import cancel causes spurious `AbortError`s in concurrent UI browse queries. Apply pragmas to both `writer` and `reader` on open, run `PRAGMA wal_checkpoint(TRUNCATE)` on `writer` (`exec`), and never call `reader.interrupt()` on import cancellation (WAL readers never block `writer`).
- 2026-11-15 SQLite errors like `SQLITE_FULL` and `SQLITE_IOERR` roll back the active transaction automatically before throwing, so an unguarded `db.exec('ROLLBACK')` in `better-sqlite3`'s `catch` throws `cannot rollback - no transaction is active` and masks the real storage error. Always wrap `ROLLBACK` cleanup in `try/catch`.
- 2026-11-15 PHP Xtream panels serialize empty associative arrays as `[]` on `get_series_info`, `get_vod_info` and `get_short_epg`, and serialize `episodes` with contiguous integer keys starting at Season `0` ("Specials") as a JSON array `[[...], [...]]` rather than an object `{"0": [...], "1": [...]}`. Accept `[]` where empty objects are expected and preserve array index `0` as Season `0` instead of `idx + 1`.
- 2026-11-15 TV list gate on the ad-hoc signed Release Apple TV simulator (`Apple TV 4K (3rd generation)`, tvOS 26.4, 100,000 items, 600 moves at 20/s): key-to-highlight p50 `16.67 ms`, p95 `16.86 ms`, max `17.17 ms` (budget `< 100 ms`), `maxJsGapMs` `6.51 ms` (budget `< 16 ms`), `losses` `0` (`#5`).
- 2026-11-15 AetherEngine's built-in URL byte source blocks until its initial 256 KiB AVIO buffer fills (about 4 s on a 500 kbit/s real-time MPEG-TS stream) and keeps superseded sockets open across rapid zaps. Feed `.liveTs` through our forward-only `LiveTsReader` (`IOReader`, `seek == -1`) backed by a partial-read `ByteFifo` (returning as soon as 1 byte is buffered after a 1,024-byte status/body sniff) and `ConnectionGate` (`URLSessionDataTask.cancel()` on stop/zap), and tune `.liveTs` startup to Candidate C (`liveStartupGraceSeconds = 0`, `liveStartupSingleSegmentMinimumSeconds = 1.0`). Across `3 x 30` zaps on `Apple TV 4K (3rd generation)` (tvOS 26.4): Candidate A (defaults) measured `316.8 / 138.0 / 226.9 ms` (`--burst 8`) vs `~2,800 / 463.8 / 541.5 ms` (`--burst 0`); B (`grace = 0`) `356.6 / 138.3 / 227.7 ms` vs `1,799.4 / 1,687.9 / 1,766.7 ms`; C (`grace = 0, minSeg = 1.0`) `289.9 / 137.0 / 218.1 ms` vs `759.3 / 652.2 / 722.6 ms` (10-min `--burst 0` soak: `0` stalls, `138.9 ms` drift, `254.4 -> 273.3 MB`); D (`C + probesize 1 MiB, analyze 1.5 s`) `366.6 / 123.9 / 251.4 ms` vs `817.2 / 646.2 / 733.8 ms`. Baseline `docs/learned/gates/player-tvos-sim.json` (commit `b283b75`, `--burst 8`, `3 x 30` zaps + 7 faults): cold `226.57 ms`, warm p50/p95 `90.88 / 147.12 ms`, zap p50/p95/max `90.89 / 147.14 / 165.89 ms`, `1` surface, `0` stale events, `0` failures, `0` limit responses, `0 ms` overlap; `drop5` and `stall` recovered, `404` and `silent` failed in time, `509` and `notice` backed off, `slowstart` left cleanly.
- 2026-11-15 Passing an audio-only live MPEG-TS URL directly to AetherEngine fails with `AVFoundationErrorDomain -11850` because URL sources with no video track fall back to bare `AVPlayer`, whereas opening through our custom `LiveTsReader` (`IOReader`) routes audio-only TS to AetherEngine's libavcodec `AudioPlaybackHost` (`ELV_AETHER route=audio ... audio=decoded`). On `Apple TV 4K (3rd generation)` (tvOS 26.4), zapping between AAC radio (`1025`) and H.264/AAC video (`1001`) (`10` zaps at `0.2/s`) measured cold `94.94 ms` / warm p50 `71.84 ms` / zap p95 `194.98 ms` (`--burst 8`) and cold `85.4 ms` / warm p50 `63.18 ms` / zap p95 `997.47 ms` (`--burst 0`), both with `0` failures, `0` limit responses and `0 ms` overlap; a 10-minute soak on `1025` (`--soak 10`) ran `599,929.13 ms` (`599,788.37 ms` position advance, `0` stalls, `181.7 -> 191.3 MB`).
- 2026-11-15 On `iPhone 17 Pro` (~83 ms warm zaps), `URLSession` delivers `didCompleteWithError(NSURLErrorCancelled)` on its delegate queue sub-millisecond before `CFNetwork`'s loader thread flushes the cancelled socket's TCP `FIN` on loopback, causing a strict 1-connection server (`sim.ts`) to reject the next `GET` with `HTTP 509` (`overlapMs: 0`). Sending `Connection: close` on progressive TS requests and waiting a `25 ms` post-close settle window in `ConnectionGate` (`settleAfterCloseMs: 25`, applied only after an older connection actually closed and cancelled immediately if superseded again) eliminated the race: baseline `docs/learned/gates/player-ios-sim.json` (`iPhone 17 Pro`, iOS 26.4, `--burst 8`, `3 x 30` zaps + 7 faults) measured cold `272.61 ms`, warm p50/p95 `108.93 / 140.58 ms`, zap p50/p95/max `108.95 / 140.59 / 153.08 ms`, `1` surface, `0` stale events, `0` failures, `0` limit responses and `0 ms` overlap (`iPad Pro 11-inch (M4)`, iOS 18.5: cold `252 ms`, warm p50/p95 `116.98 / 159.12 ms`, zap p95 `159.13 ms`, `0` limit responses).
- 2026-11-15 `0.1` Apple player exit runs (`@elv/engine-aether`, commit `6ff6142`) passed every gate judge on `Apple TV 4K (3rd generation)` (tvOS 26.4) and `iPhone 17 Pro` (iOS 26.4) with `0` crashes, `0` playback failures, `0` limit responses and `0 ms` overlap: 60-minute live soak (`--soak 60 --burst 8`, channel `1001`) ran `3,599,459.03 ms` (`3,599,398.48 ms` advance, `0` stalls, `256.5 -> 238.8 MB`) on tvOS and `3,599,254.41 ms` (`3,599,193.35 ms` advance, `0` stalls, `259.6 -> 261.6 MB`) on iOS; 600 s VOD movie-to-end soak (`--stream vod --channels 200001 --soak 15`) reached `ended: true` at `599,091.57 ms` (`0` stalls, `287.4 -> 334.1 MB`) on tvOS and `599,105.78 ms` (`0` stalls, `319.5 -> 322.7 MB`) on iOS; rapid-zap stress (`--stress --burst 8`, `3 x 200` zaps at `5/s`) measured warm p50/p95 `113.82 / 147.66 ms` (`zap max 165.13 ms`) on tvOS and `105.63 / 130.55 ms` (`zap max 153.6 ms`) on iOS (`1` surface, `0` stale events); and all 7 faults (`drop5`, `404`, `509`, `notice`, `stall`, `slowstart`, `silent`) passed on both platforms.
